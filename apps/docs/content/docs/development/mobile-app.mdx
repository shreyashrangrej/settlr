`apps/mobile` (package `mobile`) is the Android app: **Expo** (SDK 58) with
**Expo Router**, in TypeScript. It reuses `@settlr/shared` (schemas, split
math, money and date formatting) and the Convex `api` types from
`@settlr/backend/convex/_generated/api`, and talks to the same Convex
deployment as the web app, so changes on one show up live on the other.
iOS comes later.

## What's in it

The design is the Android redesign in `design/android-redesign/` (the
**Tally** design language: violet ink on cool paper, Bricolage Grotesque
for figures, Manrope for text). The bottom bar has **Home**, **Groups**,
a violet **+** in the middle, **Friends** and **Spending**.

| Screen | Route | What it does |
| --- | --- | --- |
| Welcome, Sign in, Verify | `welcome`, `sign-in`, `verify` | Google, or an email code |
| Home | `(tabs)/index` | Asks a new account its name; the Ask bar (opens the assistant), the overall balance, Settle next, balances, this month's share against the budget, upcoming bills, recent expenses |
| Groups, a group, its balances | `(tabs)/groups`, `groups/[groupId]`, `groups/[groupId]/balances` | Group cards and archived groups; a group's expenses by day, your balance, trip budget, members, archive and delete; members' balances, the settle-up plan with Record and reminders, recent payments to confirm |
| New group | `groups/new` | Name, currency, members (from friends too) |
| Friends, a friend, Add friend | `(tabs)/friends`, `friends/[friendId]`, `friends/new` | Totals, friend requests, open and settled friends; the ledger by month, Settle up, Remind, Across everything, payment confirmations |
| Add expense | `add` | Amount first on a keypad; where it goes (personal, a friend, a group), description with a guessed category, date, who paid and how it's split (equally, amounts, %, shares for groups; equally, in full or an amount with a friend), currency. Also edits (`?edit=<id>`) |
| Settle up, Settled | `settle`, `settled` | A sheet with who pays whom, full balance or part, date, note, Pay with UPI, and Slide to record; then the check and the balance before and after |
| Expense | `expense` | One expense of any kind: paid by, the split, the receipt, comments (groups), Edit, and Delete with Undo |
| Spending, Budget | `(tabs)/spending`, `budget` | The month (Everything or Personal), the budget ring, where it went, by category, tags, the month's list; the monthly budget and category limits per currency |
| Notifications, Profile, Assistant | `notifications`, `profile`, `assistant` | Requests and notifications (read on leaving); name, default currency, appearance, reduce motion, haptics, UPI id, weekly digest, the MCP connector URL, sign out; the chat |

Not built yet (they're in the mockups): attaching and scanning receipts
(the app shows them), splitting by items, another currency with a rate,
recurring expenses, the monthly recap, the receipt inbox, the trash list,
invite links, group insights and activity, Splitwise import, CSV export and
saved chats. The web app has all of them. The
[user guide's Android page](/docs/guide/android) lists them for people
using the app.

## Run it on your phone

<Steps>
  <Step>
    ### Install Expo Go

    Install **Expo Go** from the Play Store. The app runs inside it, so you
    don't need Android Studio or an Expo account.
  </Step>
  <Step>
    ### Add `apps/mobile/.env.local`

    Use the same two URLs as `apps/web/.env.local`, renamed, plus the
    deployment's `SITE_URL` (the web app the app signs in through):

    ```bash title="apps/mobile/.env.local"
    EXPO_PUBLIC_CONVEX_URL=https://<deployment>.convex.cloud
    EXPO_PUBLIC_CONVEX_SITE_URL=https://<deployment>.convex.site
    EXPO_PUBLIC_SITE_URL=https://<your-site>.vercel.app
    ```

    Without `EXPO_PUBLIC_SITE_URL` the app signs in through the
    `.convex.site` URL, where email codes work but Google doesn't.

    `EXPO_PUBLIC_*` values are inlined into the bundle, so restart the dev
    server after changing them.
  </Step>
  <Step>
    ### Start the dev server

    ```bash
    pnpm dev:mobile
    ```

    Scan the QR code with Expo Go. The phone and the computer must be on the
    same Wi-Fi; otherwise (or from a remote machine) run
    `pnpm dev:mobile --tunnel`.
  </Step>
</Steps>

## Sign in

Signed-out people start on `welcome.tsx` (Continue with Google, or with
email), then `sign-in.tsx` (the email) and `verify.tsx` (the 6-digit code).
`src/app/_layout.tsx` reads the session with `authClient.useSession()` and
guards the routes with `Stack.Protected`: signing in or out flips the
guards and the router moves to the tabs or to Welcome by itself, so screens
don't navigate after it. The session is kept in secure storage, so the app
opens signed in. [Authentication](/docs/development/auth#the-android-app)
covers how it works on the server.

To sign in from Expo Go, the deployment's `TRUSTED_ORIGINS` must include
`exp://` (the dev deployment's does). Without a real inbox, request a code
for `delivered@resend.dev` and read it with
`pnpm exec convex data --component betterAuth verification` in
`packages/backend`.

## Checks and tests

```bash
pnpm --filter mobile typecheck        # also part of pnpm typecheck
pnpm --filter mobile test             # unit tests, also part of pnpm test
pnpm --filter mobile e2e              # browser tests, also part of pnpm test:e2e
pnpm --filter mobile export:android   # bundles the app the way a release build does
```

`export:android` compiles to Hermes bytecode with an x86 binary; on an ARM
machine add `--no-bytecode` to check the bundle. `pnpm build` doesn't build
the mobile app.
[Testing](/docs/development/testing#the-android-app) explains the tests.

## Release an APK

`.github/workflows/android.yml` builds an installable APK on GitHub Actions,
without EAS: `expo prebuild` generates the native project and Gradle builds
it. Push a tag to release one:

```bash
git tag v1.0.1 && git push origin v1.0.1
```

The APK (`settlr-v1.0.1.apk`) is attached to a GitHub release of that tag.
**Run workflow** on the Actions tab builds one from any branch as a
downloadable artifact instead. Bump `version` in `apps/mobile/app.json` to
match the tag.

The app's URLs come from the repository's Actions variables
`EXPO_PUBLIC_CONVEX_URL`, `EXPO_PUBLIC_CONVEX_SITE_URL` and
`EXPO_PUBLIC_SITE_URL` (the same values as `.env.local`). The build is
signed with the Expo template's debug key: fine for installing by hand,
not for the Play Store. A signed build opens Google sign-in through the
`settlr://` scheme, which the backend always trusts.

## Layout

| Path | Contents |
| --- | --- |
| `src/app/` | Expo Router routes (the table above). `_layout.tsx` loads the fonts and saved settings, wraps everything in the Convex and Better Auth provider, guards the signed-in routes, and renders the snackbar and confirm dialog hosts |
| `src/components/` | `text` (`Text`, `Title`, `Headline`, `Sub`, `Label`), `button` (`Button`, `IconButton`, `usePressScale`), `controls` (`Chip`, `ChipRow`, `Segmented`, `Switch`, `Checkbox`, `Field`, `StepButton`), `surfaces` (`Card`, `Row`, `Rows`, `RowEnd`, `Section`, `DayHeading`, `Rise`, `Bar`, `Skeleton`, `Empty`), `tiles` (`Avatar`, `AvatarStack`, `Tile`, `GroupTile`, `CategoryTile`, `Badge`), `overlay` (`Sheet`, `SheetPage`, `toast()`, `confirm()`), `screen` (`Screen`, `StatusBarScrim`, `TabHeader`, `TopBar`), `tab-bar`, `keypad`, `slider` (Slide to record), `ring`, `ledger` (expense and balance rows shared by screens), `icons` (Lucide) |
| `src/theme/` | The Tally tokens for light and dark (`tokens.ts`: colours, label hues, radii, fonts), `useColors()`, `useIsDark()`, `useReduceMotion()` |
| `src/lib/` | Plain logic with unit tests beside it: `balances.ts` (Home's sums), `expense-form.ts` (Add expense's splits and what it sends), `keypad.ts`, `format.ts`, `category.ts` (the guessed category), `prefs.ts` (settings kept on the phone); plus `convex.ts`, `auth-client.ts`, `me.ts`, `actions.ts` (`useRun`, `errorText`), `haptics.ts` |

Imports use the `@/` alias for `apps/mobile/src`.

## Conventions

- **Design**: follow `design/android-redesign/` (open the boards in the
  canvas, or read the `.dc.html` files and `settlr.css`). Style with
  `StyleSheet` and the tokens from `useColors()`, never hex values; a
  category, group or person gets its label hue from `CATEGORY_HUE` or
  `toneFor(id)`. Cards are 24px, sheets 32px, fields 18px, tiles 15px,
  buttons and chips pills; primary actions sit at the bottom.
- **Money** says it in words: every amount carries "owes you", "you owe",
  "you lent", a sign or an arrow, in green (`owed`) or red (`owe`).
  Format with `money()` and `signedMoney()` from `@/lib/format` (whole
  amounts drop `.00`; rupees group the Indian way).
- **Text**: use `Text` from `@/components/text`, not React Native's.
  Android ignores `fontWeight` for custom fonts, so `Text` picks the
  Manrope (or, with `display`, Bricolage Grotesque) family per weight
  (500, 600, 700, 800); `tabular` turns on tabular figures for amounts.
- **Settings on the phone** (appearance, default currency, haptics, reduce
  motion, where the last expense went) are in `src/lib/prefs.ts`, saved in
  secure storage. Account settings (UPI id, digest) go through
  `api.profiles`.
- **Motion** uses React Native's `Animated` (Reanimated is installed only
  because `react-native-keyboard-controller` runs on it): cards rise in
  (`Rise`), sheets spring up, presses scale. Pushed
  screens use the stack's `default` animation, Android's own (a short
  slide with a quick fade, fully in view in about 130ms). Sheets (`Sheet`)
  rise on a spring from just below their own height, carry a drag's speed,
  and slide away in 200ms; a sheet route (`settle`, `friends/new`) leaves
  in the sheet's `onClosed`. The full-page sheets, Add expense and New
  group, are `transparentModal` routes with no native animation, wrapped in
  `SheetPage`, which springs them up over a scrim and slides them down on
  Back before the route goes. All of it stops with Android's Remove
  animations or Profile's Reduce motion (`useReduceMotion()`).
- **Press feedback**: every pressable has Android's native ripple
  (`android_ripple`), from `ripple()`/`useRipple()` in
  `components/ripple.ts`: drawn in the pressable's content colour (a dark
  wash on paper, white on violet or red), clipped to its corners with
  `overflow: 'hidden'`, borderless circles for bare icons, avatars and the
  tab bar. The web build has no ripple, so `pressedStyle()` dims instead.
- **Keyboard**: `react-native-keyboard-controller` (in Expo Go) follows the
  keyboard frame by frame, so inputs ride up and down with it. The root
  layout wraps the app in its `KeyboardProvider`; use its
  `KeyboardAvoidingView`, never React Native's (which jumps once the
  keyboard is open). It works inside sheets' `Modal`s too.
- **Status bar**: the app draws edge to edge, so the status bar is
  see-through. `Screen` paints a `StatusBarScrim` (the page's colour,
  fading out below the bar) so content scrolls away under it; a screen
  that scrolls without `Screen` renders one itself.
- **App icon**: `assets/` holds the Settlr mark (the slash and two dots of
  `Mark` in `icons.tsx`) in white on the brand violet: `icon.png`, the
  adaptive icon's foreground, background and monochrome layers, the
  splash image and the favicon.
- **Feedback**: `useRun()` runs a mutation and shows failures in the
  snackbar; `toast()` shows a message (with an action such as Undo);
  `confirm()` asks before something destructive.
- **Packages**: add them with `npx expo install <pkg>` in `apps/mobile`,
  which picks the version that matches the Expo SDK. The app has to keep
  running in Expo Go, so only use native modules that Expo Go includes.
  `react-native-web` and `react-dom` are there for the browser tests.
- **Metro** is configured for the pnpm workspace automatically; there's no
  `metro.config.js`. After adding a workspace package, restart with
  `pnpm dev:mobile --clear`.
