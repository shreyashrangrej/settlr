# CLAUDE.md

Settlr is an expense-splitting app built on TanStack Start (React 19,
file-based TanStack Router, Vite 8, Nitro) with Convex as the backend and
Better Auth for sign-in. See `README.md` for the feature overview and the
per-route SSR table.

## Commands

Use **pnpm** only (no npm/yarn lockfiles).

```bash
pnpm install
pnpm dev              # http://localhost:3000
pnpm dev:convex       # push convex/ to the dev deployment on every change (run alongside dev)
pnpm typecheck        # tsc --noEmit
pnpm build            # vite build → .output/ (Nitro, node-server preset by default)
pnpm start            # run the production build
pnpm generate-routes  # regenerate src/routeTree.gen.ts without starting dev
```

There is no test suite or linter yet. Before committing, run
`pnpm typecheck && pnpm build`. The build is also what enforces the
server/client import boundary.

## Git workflow

Always push finished work to `main` on GitHub, unless the user says
otherwise for a given change. If you work on a feature branch, push it and
then fast-forward `main` to it (`git push origin HEAD:main`). Never
force-push `main`.

## Layout

- `convex/`: the Convex backend, where all app data lives. `schema.ts`
  (friends, friendEntries, groups, groupExpenses, personalExpenses),
  `friends.ts`, `groups.ts`, `personal.ts` (queries and mutations), and
  `lib/` (`requireUser`, value checks in `input.ts`, balance math in
  `ledger.ts`, enum validators). `auth.ts` is the Better Auth instance
  (email OTP + Google), `http.ts` mounts its routes, `convex.config.ts`
  mounts the `betterAuth` component and declares the typed deployment env
  vars. `convex/_generated/` is generated by `convex dev`; commit it.
  Import it from `src/` as `#convex/_generated/api`.

- `src/routes/`: file-based routes. `src/routeTree.gen.ts` is generated by the
  router plugin. Never edit it by hand, but do commit it. `_app.tsx` is the
  pathless signed-in layout (redirects to `/` when signed out); the
  dashboard, friends, groups and personal pages live under `_app/`.
- `src/functions/*.functions.ts`: `createServerFn` server functions. These are
  the only bridge from UI code to server-only modules (today: the auth
  session for SSR).
- `src/server/`: server-only code (`auth.server.ts`).
- `src/lib/`: isomorphic code. `schemas.ts` holds the zod schemas shared by
  search params, forms and server functions. The rest is `types.ts`,
  `format.ts`, `preferences.ts` (localStorage, via `createClientOnlyFn`),
  `theme.ts` (light/dark) and `utils.ts` (shadcn's `cn`).
- `src/components/ui/`: shadcn/ui components built on **Base UI**
  (`@base-ui/react`, style `base-nova` in `components.json`), not Radix.
  Add more with `pnpm dlx shadcn@latest add <name>`.
- `src/components/`: app components. `page-header.tsx` (`PageHeader`,
  `SplitLayout`), `ledger.tsx` (`useAction` for mutations with toasts,
  `SignedAmount`, `BalanceText`, `PersonAvatar`), `form-fields.tsx`
  (`SelectField`, `CurrencySelect`, `CategorySelect`, `AmountInput`),
  `confirm-action.tsx` (destructive actions behind an alert dialog),
  `account-menu.tsx` (avatar dropdown with sign-out).
- `src/styles.css`: design tokens (`--bg`, `--surface`, `--accent`, ...),
  mapped to shadcn color names in `@theme inline` (plus `positive`), and the
  landing hero's CSS.
- Auth on the web side: `src/lib/auth-client.ts` (browser client and the
  sign-in actions), `src/server/auth.server.ts` (proxy handler and token),
  `src/routes/api/auth/$.ts` (forwards `/api/auth/*` to Convex) and
  `src/functions/auth.functions.ts`. The root route loads the token in
  `beforeLoad`, so `isAuthenticated` is in route context during SSR.
- `src/start.ts`: global request middleware (CSRF on non-GET requests).
- `src/router.tsx`: router instance, the TanStack Query client wired to
  Convex (`ConvexQueryClient`), and default pending, error and not-found
  components.

## Conventions

- **Server-only code** goes in `*.server.ts` files, or behind
  `createServerOnlyFn`. Start's import protection fails the build if a
  `.server` file reaches the client bundle. In dev it only warns.
  Route/component files must reach server code through server functions,
  never by importing `src/server/*` directly. `src/functions/*` may import it
  because the compiler strips handler bodies from the client bundle. Keep
  top-level (non-handler) code in those files free of server-only calls.
- **Data** goes through Convex, not server functions. Loaders prefetch with
  `context.queryClient.ensureQueryData(convexQuery(api.x.y, args))` and
  components read with `useSuspenseQuery(convexQuery(...))`; the same query
  becomes a live subscription in the browser, so don't call
  `router.invalidate()` after mutations (`useConvexMutation`). Queries that
  take an id from the URL accept a string, `normalizeId` it and return
  `null` for missing or foreign rows; the loader turns that into
  `notFound()`.
- **Convex functions** get the user from `requireUser(ctx)` (keyed by
  `tokenIdentifier`) and scope every read and write to it. Check values with
  `convex/lib/input.ts` using the same limits as the zod form schemas, and
  throw `ConvexError('plain-language message')` for anything the user can
  fix; the UI shows it via `errorMessage()` in `src/lib/errors.ts`. Totals
  shown on every page load are stored on the parent document and updated in
  the same mutation (`convex/lib/ledger.ts`). Read
  `convex/_generated/ai/guidelines.md` first.
- **Server functions** use `.validator(zodSchema)` (`inputValidator` is
  deprecated) and re-validate everything.
- **Search params** are validated with zod schemas that use
  `.default(x).catch(x)` on every field, so bad URLs fall back instead of
  throwing. Defaults are stripped from the URL with `stripSearchParams`, and
  the loader declares `loaderDeps`.
- **Money** is stored as integer minor units (`amountCents`), never floats.
  All currencies in `CURRENCIES` have 2 decimals.
- **Hydration safety**: SSR-rendered routes format with the fixed `en-US`
  locale and UTC (`src/lib/format.ts`). Anything that depends on the viewer's
  locale, time zone, clock or browser storage belongs in an `ssr: 'data-only'`
  or `ssr: false` route, or in a `useEffect`. For the viewer's locale use
  `new Intl.NumberFormat().resolvedOptions().locale`, not
  `navigator.language`, which can be an invalid tag such as `en-US@posix`.
- **Styling**: use shadcn components and Tailwind utilities (no new
  hand-written CSS). Base UI uses a `render` prop, not `asChild`: e.g.
  `<Item render={<Link to="..." />}>` or `<DropdownMenuTrigger
  render={<Button />}>`. For a link that looks like a button, put
  `buttonVariants(...)` on a `<Link>`. Confirm destructive actions with
  `ConfirmAction`, not `window.confirm`, and report success with
  `useAction(fn, { success: '...' })` (a sonner toast).
- **Layout**: pages span the full width, so use the width for more content,
  not wider components. Summary figures go in a `StatGrid` of `StatCard`s
  (`src/components/stat-card.tsx`), lists of records are tables whose extra
  columns appear on wider screens (`hidden md:table-cell`, with the details
  folded into the first cell below that), collections of things (friends,
  groups) are card grids with `repeat(auto-fill,minmax(…,1fr))`, and forms
  get a max width. `SplitLayout` gives a page a main area and a 24rem
  sidebar.
  Dark mode is the `.dark` class on `<html>` (set before paint by the inline
  script in `__root.tsx`), not `prefers-color-scheme`, so style dark variants
  with `.dark` / `dark:`. Theme-dependent markup must render the same on the
  server, e.g. render both icons and hide one with `dark:hidden`.
  Element-level CSS rules go in `@layer base`, or they override Tailwind
  utilities.
- Imports use the `#/` alias for `src/` (e.g. `#/lib/schemas`).

## Gotchas

- Convex deployment env vars (`pnpm exec convex env list`): `SITE_URL`
  (the app origin; Better Auth rejects other origins, so test auth on
  http://localhost:3000), `BETTER_AUTH_SECRET`, and optional
  `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` (Google sign-in is off until
  both are set) and `RESEND_API_KEY`/`AUTH_EMAIL_FROM`. Without a Resend
  key, sign-in codes are only logged: read them with
  `pnpm exec convex logs`. Set values with the `NAME=value` form.
- `better-auth` is pinned to the exact version `@convex-dev/better-auth` is
  built against (1.6.15). Newer 1.6.x releases break the
  `ConvexBetterAuthProvider` types. Upgrade the two together.
- To call Convex functions from the CLI as a test user, run the CLI with
  node, not `pnpm exec` (cmd.exe mangles the JSON on Windows):
  `node node_modules/convex/bin/main.js run --identity '{"tokenIdentifier":"test|u1","name":"Test"}' friends:list '{}'`.
- To sign in locally without a real inbox, request a code for
  `delivered@resend.dev` (Resend's test address) and read it with
  `pnpm exec convex data --component betterAuth verification`.
- A running `pnpm dev` scaffolds any new, empty route file with placeholder
  content. Create route files in one write (not `touch` then edit).
- Requests with a bot user agent (including plain `curl`) get fully buffered
  HTML. To observe streaming, send a browser `User-Agent`.
- Deployment target: `NITRO_PRESET=<preset> pnpm build`. No app code changes
  are needed. `nitro` is a beta and is pinned to an exact version on purpose.
- `shadcn add` writes `import { cn } from "cn"` and installs an unrelated npm
  package named `cn`. After adding components, change the import to
  `#/lib/utils` and run `pnpm remove cn`. It may also add `next-themes`
  (for sonner); this app's toaster follows the `.dark` class instead, so
  remove it. Don't re-run `shadcn init`: it would overwrite the theme in
  `styles.css`. The `data-horizontal`/`data-vertical` variants that init
  would add are defined there by hand.
- After adding packages while `pnpm dev` is running, Vite may re-bundle
  dependencies mid-session and the page errors with "Invalid hook call"
  (two copies of React). Reload the page.
