# CLAUDE.md

Settlr is an expense-splitting app built on Next.js 16 (App Router, React
19, Turbopack) with Convex as the backend and Better Auth for sign-in. See
`README.md` for the feature overview and the per-route rendering table.

## Commands

Use **pnpm** only (no npm/yarn lockfiles).

```bash
pnpm install
pnpm dev              # http://localhost:3000
pnpm dev:convex       # push convex/ to the dev deployment on every change (run alongside dev)
pnpm typecheck        # next typegen && tsc --noEmit
pnpm build            # next build → .next/
pnpm start            # run the production build
```

There is no test suite or linter yet. Before committing, run
`pnpm typecheck && pnpm build`. The build is also what enforces the
server/client boundaries (`server-only` imports, client functions called
from server components).

## Git workflow

Always push finished work to `main` on GitHub, unless the user says
otherwise for a given change. If you work on a feature branch, push it and
then fast-forward `main` to it (`git push origin HEAD:main`). Never
force-push `main`.

## Layout

- `convex/`: the Convex backend, where all app data lives. `schema.ts`
  (friends, friendEntries, groups, groupExpenses, personalExpenses,
  receipts, budgets, notifications), `friends.ts`, `groups.ts`,
  `personal.ts`, `budgets.ts`, `notifications.ts`, `receipts.ts` (queries
  and mutations), `assistant.ts` (the `/assistant` chat: an action that
  calls OpenRouter with tool calling, plus the internal queries its search
  and edit tools read through; the tools, in `lib/assistantTools.ts`, write
  through the public mutations above as the caller, and deleting is only
  offered, the user confirms it in the chat), and `lib/` (`requireUser`, value checks in `input.ts`,
  balance math in `ledger.ts`, receipt attach/delete in `receipts.ts`, enum
  validators). `auth.ts` is the Better Auth instance
  (email OTP + Google), `http.ts` mounts its routes, `convex.config.ts`
  mounts the `betterAuth` component and declares the typed deployment env
  vars. `convex/_generated/` is generated by `convex dev`; commit it.
  Import it from `src/` as `#convex/_generated/api`.

- `src/app/`: the App Router. `layout.tsx` is the root document (reads the
  auth session, renders the header and `<Providers>`), `page.tsx` the
  landing hero. `(app)/` is the signed-in area: its layout redirects to `/`
  when signed out, and the dashboard, friends, groups, personal, budget,
  notifications and receipt viewer pages live under it. Each page is a
  server `page.tsx` that prefetches data and renders a client `view.tsx`
  beside it; `loading.tsx` is its skeleton. Route groups `(list)`,
  `(detail)` and `(expenses)` only exist to give sibling pages their own
  `loading.tsx` (a folder's `loading.tsx` also covers everything nested in
  it). `api/auth/[...all]` proxies Better Auth to Convex; `api/health` is a
  liveness probe.
- `src/server/`: server-only code (every file imports `server-only`).
  `auth.server.ts` (Better Auth's Next.js adapter: `handler`, `getToken`,
  `fetchAuthQuery`, and the per-request `getAuthSession()`) and
  `convex.server.ts` (`prefetchQuery`).
- `src/lib/`: isomorphic code. `schemas.ts` holds the zod schemas shared by
  search params and forms. The rest is `types.ts`,
  `format.ts`, `search.ts` (`parseSearch`, `searchHref`), `preferences.ts`
  (localStorage; throws on the server), `theme.ts` (light/dark) and
  `utils.ts` (shadcn's `cn`).
- `src/components/ui/`: shadcn/ui components built on **Base UI**
  (`@base-ui/react`, style `base-nova` in `components.json`), not Radix.
  Add more with `pnpm dlx shadcn@latest add <name>`.
- `src/components/`: app components. `page-header.tsx` (`PageHeader`,
  `SplitLayout`), `ledger.tsx` (`useAction` for mutations with toasts,
  `SignedAmount`, `BalanceText`, `PersonAvatar`), `form-fields.tsx`
  (`SelectField`, `CurrencySelect`, `CategorySelect`, `AmountInput`,
  `DatePicker`), `receipts.tsx` (`ReceiptField` upload control,
  `ReceiptLink`), `edit-dialog.tsx` (edit a row in a dialog),
  `group-expense-form.tsx` (add/edit a group expense), `notifications.tsx`
  (rows shared by the bell dropdown and the page), `month-nav.tsx`,
  `confirm-action.tsx` (destructive actions behind an alert dialog),
  `account-menu.tsx` (avatar dropdown with sign-out). Framework glue:
  `providers.tsx` (Convex + TanStack Query clients, `useSession()`),
  `prefetched.tsx` (`<Prefetched>`), `client-only.tsx` (`<ClientOnly>`),
  `nav-link.tsx` (`<NavLink>`, sets `data-status="active"`),
  `navigation-progress.tsx` (top bar, `useAppRouter()`), `site-header.tsx`.
- `src/styles.css`: design tokens (`--bg`, `--surface`, `--accent`, ...),
  mapped to shadcn color names in `@theme inline` (plus `positive`), and the
  landing hero's CSS.
- Auth on the web side: `src/lib/auth-client.ts` (browser client and the
  sign-in actions), `src/server/auth.server.ts` (proxy handler, token and
  session) and `src/app/api/auth/[...all]/route.ts` (forwards `/api/auth/*`
  to Convex). The root layout reads the session on the server and hands it
  to `<Providers>`, so client components get the user from `useSession()`.
- `src/app/error.tsx` and `not-found.tsx`: the error and 404 states.

## Conventions

- **Server vs client components**: files under `src/app` are server
  components unless they start with `'use client'`; `view.tsx`, most of
  `src/components` and the Base UI parts of `components/ui` are client
  components. A server component may render client components but can't
  call functions exported from a `'use client'` module (e.g.
  `buttonVariants()`: it fails at request time), so keep server components
  to data loading and composition. Server-only code lives in `src/server/`
  and imports `server-only`.
- **Data** goes through Convex, not server actions. A server `page.tsx`
  (or layout) prefetches with `await prefetchQuery(api.x.y, args)` and
  wraps its view in `<Prefetched queries={[result.entry]}>`; the view reads
  with `useSuspenseQuery(convexQuery(api.x.y, args))`, which in the browser
  becomes a live subscription, so don't call `router.refresh()` after
  mutations (`useConvexMutation`). Pass the args in the same key order on
  both sides: Convex hashes query keys with `JSON.stringify`. Queries that
  take an id from the URL accept a string, `normalizeId` it and return
  `null` for missing or foreign rows; the page turns that into
  `notFound()`. Dynamic titles use `generateMetadata`, which can call
  `prefetchQuery` too (it's cached per request).
- **Session**: `getAuthSession()` on the server (cached per request),
  `useSession()` in client components. Layouts don't re-render on client
  navigation, so anything that changes who is signed in or their profile
  must call `router.refresh()` (sign-in pushes to `/dashboard` then
  refreshes; sign-out does a full page load to `/` so nothing of the
  account stays in memory).
- **Navigation**: `next/link` with string hrefs, `<NavLink>` for links that
  show the current page, `useAppRouter()` (from `navigation-progress.tsx`)
  instead of `useRouter()` for programmatic navigation so the progress bar
  shows. `useParams()` works in client components; pages pass params and
  parsed search params down as props.
- **Search params** are parsed on the server with
  `parseSearch(zodSchema, await searchParams)`; the schemas use
  `.default(x).catch(x)` on every field (and `z.coerce` for numbers), so bad
  URLs fall back instead of throwing. Build URLs with `searchHref(pathname,
  values, defaults)`, which leaves defaults out.
- **Money** is stored as integer minor units (`amountCents`), never floats.
  All currencies in `CURRENCIES` have 2 decimals.
- **Hydration safety**: SSR-rendered routes format with the fixed `en-US`
  locale and UTC (`src/lib/format.ts`). Anything that depends on the viewer's
  locale, time zone, clock or browser storage goes inside `<ClientOnly>`
  (the page can still prefetch its data) or in a `useEffect`. Values like
  "this month" and "today" are computed in the server page and passed down. For the viewer's locale use
  `new Intl.NumberFormat().resolvedOptions().locale`, not
  `navigator.language`, which can be an invalid tag such as `en-US@posix`.
- **Styling**: use shadcn components and Tailwind utilities (no new
  hand-written CSS). Base UI uses a `render` prop, not `asChild`: e.g.
  `<Item render={<Link href="..." />}>` or `<DropdownMenuTrigger
  render={<Button />}>`. For a link that looks like a button, put
  `buttonVariants(...)` on a `<Link>`. Confirm destructive actions with
  `ConfirmAction`, not `window.confirm`, and report success with
  `useAction(fn, { success: '...' })` (a sonner toast).
- **Layout**: pages span the full width, so use the width for more content,
  not wider components. Summary figures go in a `StatGrid` of `StatCard`s
  (`src/components/stat-card.tsx`), lists of records are tables whose extra
  columns appear on wider screens (`hidden md:table-cell`, with the details
  folded into the first cell below that), collections of things (friends,
  groups) are card grids with `repeat(auto-fill,minmax(…,1fr))`, and forms
  get a max width. `SplitLayout` gives a page a main area and a 24rem
  sidebar.
- **Loading**: give each page a `loading.tsx` rendering its page-shaped
  skeleton from `src/components/skeletons.tsx`. The top bar
  (`navigation-progress.tsx`) starts on link clicks and `useAppRouter()`
  navigations. Nested pages pass `back={{ fallback: '/path', label }}` to
  `PageHeader` for a back button.
- Dark mode is the `.dark` class on `<html>` (set before paint by the inline
  script in `src/app/layout.tsx`), not `prefers-color-scheme`, so style dark variants
  with `.dark` / `dark:`. Theme-dependent markup must render the same on the
  server, e.g. render both icons and hide one with `dark:hidden`.
  Element-level CSS rules go in `@layer base`, or they override Tailwind
  utilities.
- Imports use the `#/` alias for `src/` (e.g. `#/lib/schemas`).

## Gotchas

- Convex deployment env vars (`pnpm exec convex env list`): `SITE_URL`
  (the app origin; Better Auth rejects other origins, so test auth on
  http://localhost:3000), `BETTER_AUTH_SECRET`, and optional
  `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` (Google sign-in is off until
  both are set) and `RESEND_API_KEY`/`AUTH_EMAIL_FROM`. Without a Resend
  key, sign-in codes are only logged: read them with
  `pnpm exec convex logs`. The assistant needs `OPENROUTER_API_KEY` and
  `OPENROUTER_MODEL` (an OpenRouter model slug that supports tool calling);
  without them `/assistant` says it isn't set up. Set values with the
  `NAME=value` form.
- `better-auth` is pinned to the exact version `@convex-dev/better-auth` is
  built against (1.6.15). Newer 1.6.x releases break the
  `ConvexBetterAuthProvider` types. Upgrade the two together.
- To call Convex functions from the CLI as a test user, run the CLI with
  node, not `pnpm exec` (cmd.exe mangles the JSON on Windows):
  `node node_modules/convex/bin/main.js run --identity '{"tokenIdentifier":"test|u1","name":"Test"}' friends:list '{}'`.
- To sign in locally without a real inbox, request a code for
  `delivered@resend.dev` (Resend's test address) and read it with
  `pnpm exec convex data --component betterAuth verification`.
- `.env.local` needs `NEXT_PUBLIC_CONVEX_URL` and
  `NEXT_PUBLIC_CONVEX_SITE_URL` (the `.convex.site` URL). `NEXT_PUBLIC_*`
  values are inlined at build time, so rebuild after changing them.
- Pages with a `loading.tsx` stream: the status is sent before the page
  finishes, so a `notFound()` there still responds 200 (with the not-found
  UI and a `noindex` tag).
- Deployment: any Next.js host (Vercel, or `pnpm build && pnpm start` on
  Node). `transpilePackages` in `next.config.ts` compiles
  `@convex-dev/better-auth`.
- `ui.shadcn.com` may be blocked in sandboxed environments. The registry
  sources are on GitHub (`apps/v4/registry/bases/base/ui/*.tsx`, with the
  nova style's `cn-*` classes in `apps/v4/registry/styles/style-nova.css`);
  `calendar.tsx` and `popover.tsx` were added from there by hand.
- `components.json` has `"rsc": true`, so `shadcn add` puts `'use client'`
  on components that need it; check hand-copied ones do too.
- `shadcn add` writes `import { cn } from "cn"` and installs an unrelated npm
  package named `cn`. After adding components, change the import to
  `#/lib/utils` and run `pnpm remove cn`. It may also add `next-themes`
  (for sonner); this app's toaster follows the `.dark` class instead, so
  remove it. Don't re-run `shadcn init`: it would overwrite the theme in
  `styles.css`. The `data-horizontal`/`data-vertical` variants that init
  would add are defined there by hand.
- After adding packages while `pnpm dev` is running, restart it.
